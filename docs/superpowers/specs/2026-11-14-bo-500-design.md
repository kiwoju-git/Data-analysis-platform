# BO 500-Trial Capacity

Status: owner approved (2026-11-14). The owner approved the proposed total of
500 existing observations plus subsequent trials, without sampling.

## Intent And Scope

Import all 240 observations in the reported workflow and support up to 500
total trials in scalar, desirability, mixed-factor and mixture BO studies.
Completed, pending and abandoned trials all consume the total trial limit.
At 500 completed observations, fitting and inspecting a saved model remain
valid; creating trial 501 does not. Importing 501 valid rows fails atomically.
Rows filtered or explicitly excluded under the existing missing policy do not
count as imported observations; repeated observations each count separately.

## Approaches

Raising only the import limit was rejected because downstream fitting, readers,
confirmation, reports and SQLite constraints also enforce 200. The approved
approach extends the entire bounded lifecycle to 500, preserving time, thread,
optimization and acquisition budgets. No automatic sampling or approximate GP
is introduced. Larger memory/time costs are measured, not described as free.

## Constraints And Compatibility

- Keep exact GP equations, defaults and numeric tolerances unchanged.
- Preserve old artifact bytes, hashes, policies and original saved budgets.
- No changes to user data or workspaces during tests; synthetic workspaces only.
- No dependency upgrade. Python 3.10 and CPU-only remain required.
- Initial generated LHS limits, optimizer iteration limits, query chunk sizes,
  candidate limits and standalone GPR limits are not trial limits.
- Migrate real SQLite CHECK constraints additively, with rollback on failure
  and foreign-key/integrity checks. Do not rewrite historical migration SQL.
- Increase runtime API compatibility and metadata only as needed by the actual
  contract and migration; no statistical method-version bump for this capacity.
- Use bounded prediction chunks and existing worker deadlines. Do not claim an
  OS-enforced memory limit where only an estimate/check is implemented.
- Limit errors show a localized count/maximum, not the generic mapping error.
- No GitHub push or Linux release in this task. Keep the current user preview
  and its form intact until a verified build can be offered separately.

## Acceptance

200/201/240/500 accepted; 501 rejected. Confirm at 499 permits one trial but not
a partial two-trial batch. At 500, no further pending trial is created. Real
240- and 500-row two-response fits, snapshot restoration and prediction are
checked with bounded settings and timing/memory recorded. A built-app synthetic
240-row import and recommendation journey verifies the visible end-to-end path.
Migration from metadata 37 preserves existing records and artifact checksums.
Unexecuted native CI/platform checks are explicitly reported.
